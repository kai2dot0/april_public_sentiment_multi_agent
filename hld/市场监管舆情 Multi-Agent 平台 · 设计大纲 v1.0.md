# 市场监管舆情 Multi\-Agent 平台 · 设计大纲 v1\.0

> **范围界定**：以原投标方案的业务目标为输入，**不训练、不微调、不做基础模型能力研究**；只设计并实现框架层：数据采集、多 Agent 编排、并发与可靠性、热插拔扩展、知识层、证据与质量保障。大模型（含嵌入模型）视为外部可替换资源，经统一网关接入。**必须评估"模型 + 提示词 + 检索 + 规则"组合后的系统输出质量。**

> **根本约束**：Demo 允许实现不完整，不允许破坏已承诺的语义与边界（第 2 章）；迟早要有的能力现在留缝（第 12 章）。

## 0. 结论先行

1. **架构方向不变**：事件驱动 + 能力声明；流式段订阅，产出段显式工作流按查询拉取。
2. **证据身份只绑不可变出处**；blob 按（租户，摘要，实例 ID）成行、三态 `pending | live | condemned`，上传按"插 pending 行 → 写字节 → 改 live"三步；**字节写入受实例状态约束**（Demo 在 PG 短事务内校验仍为 pending；生产档写入凭证一律限时、按实例独立密钥上传前加密），回收时机按存储策略计算 `reclaim_not_before`，清理责任在凭证失效加服务端最长写入耗时后可闭合；上传与等待在登记事务之外完成。**引用记账以持有者为单位**，所有 −1 以 ON CONFLICT DO NOTHING 写入并按持有关系键排序。
3. **控制对象两种处置**：永久撤回走**写屏障**；临时原因只递增 availability 版本、`FOR NO KEY UPDATE`，**比较基准在来源配置锁中固定**（可信上游事件时间 / 单一权威位置域 + handoff\_epoch / 按提交顺序，后者清除类须经保持与回访），状态未变也推进位置。**无法定序的冲突一律登记到每（账号，原因）唯一的保守保持**，保持期间按"已设置"处理（交接核对保持例外：不新增禁读，只阻止清除）；保持期间生效的设置类信号若不能证明新于保持中全部冲突，则在应用的同时并入保持；每个保持至多一个在途回访，回访按观测结论对应的判定基准时刻校验覆盖证明（观测为"未设置"须晚于最后一次并入；观测为"已设置"须晚于最后一次并入的清除或无法定序冲突，之后单独并入的设置不使其失效），写回在账号控制行锁内复核；unresolved 不再生成回访，由持久化核验预算驱动、耗尽转人工；观测为"已设置"的回访不因之后并入的设置失效；回访确认"已设置"后，清除须证明发生于参照时刻（回访观测与最后一次并入中较晚者）之后，接收时刻证明只用于实时送达，且只用首次可信入口接收时刻与明确覆盖账号控制事件的 guarantee；账号永久撤回时同事务关闭其全部保持。**作业代次变更协议**：同一作业串行；栅栏同时拦截领取与新建——新建任务的事务在作业行 `FOR NO KEY UPDATE` 锁内复核代次与栅栏并持锁至提交；登记默认终结目标；锁全部非终态旧代次任务行；改代次，旧代次心跳不再续租；扫尾只终结未领取或租约失效的旧任务；已因代次变更终结的任务收到合法旧包时，在已持任务行锁的同一事务内只做受限控制投影，按（任务，租约代次，语义摘要）幂等；第 ⑫ 步作业行 CAS 同时校验代次、栅栏与检查点版本，代次 / 栅栏不匹配为正常拦截路径，仅检查点版本冲突则撤销租约、退回排队。临时不可用按原因分别登记，只做读时门控；**逐文档核验按范围分别保存**，两条推进路径——任何带新鲜性下界的存在观测下界 ≥ verification\_cut\_at，或可靠增量路径每次送达自动记录的 `new_after_cut`；排序域变化即建新核验代次，无缝切换须验证映射有重叠、无缺口且衔接覆盖；缺失观测（多资源 missing 与单资源 gone 同一规则）新鲜性下界已知时须严格晚于存在证据保守上界才计入删除确认，present 只经抬高该上界打断计数；下界未知按版本化来源策略并在审计中区分，此类计入遇其后登记的任何 present 即失效。
4. **采集决策表封口**：verdict + 全部违规码 + primary 取编号最小；18 行动作 + 19 条违规；完备性测试排除不可达上下文。采集任务全部终态调用作业责任结算；continuous 周期由边界后第一次当前代次作业级事务逐窗结算。
5. **Demo 基线**为单任务（`max_batch=1`）、单转发器、直连 PG；桩化与未实现分别登记，未实现项在 §12 均有归属阶段。
6. **Manifest、Claim 状态、提交结局、分段收口在本文完整定义**；缺省展开进 Run 配置锁；`supports_resume` 与 `execution_form`、`continuity` 分开声明；"控制信号"仅指 `tombstones[]` 与账号控制信号。
7. **工期：2 人 13 周**，缓冲前移（M0 4.5 / M1 5.5 / M2 2 / M3 1 周）；估算 24.3 / 容量 26.0，里程碑余量 1.0 / 0.4 / 0 / 0.3；每人每里程碑负荷均 ≤ 个人容量。**有条件计划**：外部标注、领域专家、Bluesky 与新闻 RSS 两类来源合规确认按 M0 前到位。

## 1. 为什么改原投标方案的架构

| 原方案               | 问题            | 本设计                                   |
| ----------------- | ------------- | ------------------------------------- |
| 分析→预警→报告三层硬管线     | 新增能力必须改上下游    | 事件驱动 + 能力声明；两段式编排                     |
| Drools 定级与大模型定级并存 | 权威不明，不可复现     | 规则定级，模型只做解释与建议                        |
| 模型自报置信度           | 自证式指标         | 运行时盖戳；版本化放行策略                         |
| 结构化数据、法规、案例统称 RAG | 检索语义不同        | 知识四分治 + 知识快照定义                        |
| 溯源只绑"表名 + 字段名"    | 句子与数据无强绑定     | Claim 级溯源、四类证据、报告槽位                   |
| 无实体归一化            | 按主体聚合的统计全错    | entity-resolver；ID 只增不删 + 重定向 + 类型化关系 |
| 无执行状态、无恢复语义       | Demo 成功依赖不出故障 | Worker 协议 + 任务表 + 租约 + 外发箱            |
| 业务词写死             | 换行业等于重写       | 领域包（发布期）+ 知识服务（运行期）                   |
| 采集来源无说明           | 合规与成本黑洞       | 连接器插件 + 合规清单 + 删除义务 + 分池资源模型          |

### 2.3 桩化规范

真接口真契约；Null/Fake/Real 同工厂；`produced_by.impl` 表本组件，模拟来源经 `flags.contains_simulated_input` 沿链传播；回执 `delivered / skipped / simulated / failed / unsupported`；桩可切报错且永不返回成功态；CI 禁工厂外读 Demo 配置。

### 2.4 代码分层与依赖图

```
apps/  agents/  connectors/  sdk/  runtime/  capabilities/  adapters/  spi/  contracts/  domain-packs/
```

`contracts/`、`spi/`（PlatformConnector Protocol、受控传输接口、总线、存储、模型、鉴权）不依赖其他包；`sdk/`（Worker 协议客户端、状态 API、证据 API、网关客户端、受控传输 HTTP + WebSocket、领域包注入、连接器插件加载器、**统一 ID 派生函数**）依赖 contracts + spi，不依赖 runtime；`agents/` 只依赖 contracts + sdk，不 import connectors/，经 SDK 装配得到钉版本的连接器能力；`connectors/` 只依赖 contracts + spi + sdk，import-linter 禁止 httpx、requests、aiohttp、websockets、`urllib.request`、`http.client`、socket（允许 `urllib.parse`），真正执法是进程组级网络策略；`runtime/`、`capabilities/` 不依赖 agents/connectors；`adapters/` 只放基础设施实现；政务部署的 composition root 不装配投放实现；SDK 处理签名 `handle(tasks: list)`，Demo 批大小 1。

## 3. 总体架构

### 3.1 分层

控制台 / 对外 API → 编排层（集中分发 ≥2 实例；流式段 / 产出段 / 提交路径含运行时侧校验）→ Agent 运行层（按池与按连接器的独立 worker 进程组）→ 能力层（网关、知识服务、证据库、规则引擎、Registry、配额、执行上下文、凭据代理、受控传输层、**撤回控制通道**）→ 本体层（类型层）→ 基础设施（Kafka、PostgreSQL 直连连接池、Redis、OTel/Prom）。Redis 只做令牌桶与冷却的加速镜像，权威在 PG。

### 3.2 两段式编排

**流式段**纯订阅；整链超时只告警；stalled trace 由 TTL 归档。  
**产出段**由 `report.requested` 启动，按查询拉取。三种量：采集检查点 / 已纳入数据处理前沿 / 来源覆盖声明。**CaptureCoverage**：查询窗口、采集周期、已观察来源前沿、`complete | truncated | unknown`、观察截止时间、依据。  
**报告就绪判定式**（两级结论）：**完整**要求报告范围内每个来源同时满足——该来源 CaptureCoverage 为 `complete` 且覆盖目标查询范围、无截断、无与窗口相交的未闭合或不可恢复缺口（**处于来源范围读时门控中的来源、以及含有**与报告窗口相交（按文档业务时间）**的逐文档核验条件未满足文档的来源，视为未闭合缺口；缺口期间经任何路径首次观察、尚未核验的文档同样计入**）；`late_arrival_bound.kind = guarantee` 且 `观察截止时间 ≥ 窗口结束 + 保证值`；已接收集合的处理前沿达所需阶段。**相对本次观察**：来源迟到上限为经验 SLO 或 unknown 时，不把未知上限当算术项，按来源配置的版本化等待策略（最长等待时长 + 采集周期结束条件）判定就绪，结论标"相对本次观察"，并披露截断、缺口与未完成计数；coverage 为 `truncated / unknown` 的来源只能进入此级。迟到保证只约束迟到，不替代覆盖判定：guarantee + truncated 不得标完整。resync 恢复不删除不可恢复区间记录，不把 partial 升为 complete。不比较任意检查点值与时间。不满足等到超时，超时后在快照记录缺口。**ReportInputSnapshot** 短事务冻结选中 Claim 版本与证据、指标结果、实体映射版本、包与知识快照、coverage 版本与 readiness 结果、计数；读取服从当前可用性检查。  
**集中分发**：编排器持久化输入记录、路由快照、派生任务后才推进 offset；消费位点与物化同事务写 PG，与分区所有权代次同行。**Registry 版本对账**为真相，LISTEN/NOTIFY 走专用直连会话只加速。

### 3.3 核心组件

**PG 事件表唯一权威日志**；回放从 PG 生成任务（causal 按 subjectseq、arrival 按原始物化位次）；无消费者事件保留并记录处置。生产者以 `partition_key` 作 Kafka 消息键；causal 流固定域→分区映射。  
**Model Gateway**：吞吐容量配额；精确请求结果缓存（结论/定级/指标禁近似复用）；schema 强制；重试只管传输类；模型输出由网关服务端写入证据库；提示词中来源内容只能经 SDK 从证据引用填入，网关据此登记反向索引（lint + 抽检）；工具白名单；检索文本按不可信数据处理；secrets。  
**受控传输层**：HTTP 与 WebSocket 统一限流（`rate_scope` 按凭据 / 按主机）、Retry-After 与 429 持久化冷却、出站白名单、审计、计量；传输重试与作业重试共用预算；网络等待不持有 DB 连接。  
**凭据代理**（Demo **未实现**：接线用 Fake，真实刷新能力声明 `unsupported`，依赖刷新成功的计划在解析时拒绝）：刷新单点（PG 行租约）、secrets 版本 CAS、刷新失败状态、锁丢失不覆盖新凭据、同账号同权限刷新不递增 `job_generation`——以上为接口与规则定义，Phase 2-A 实现。  
**撤回控制通道**：撤回事件按**全局撤回日志序号**广播给运行时进程与声明缓存的 worker。**序号分配**：在登记撤回的事务内经单行计数器分配（计数行 `FOR UPDATE`，持锁至提交），保证无空洞且号码顺序即提交可见顺序；计数行在全局锁序中位于控制对象行之后、blob 行之前，仅当本包含控制变更时获取；撤回登记因此串行化（撤回频率低，可接受）。各进程回报的是**连续已处理前沿**（不是收到的最大序号），键为 `process_instance_id`；进程启动或重新注册前必须完成缓存清空并以当时的撤回日志前沿注册（缓存为空即视为已失效）。**心跳失联**：先将进程隔离并撤销执行资格（租约失效）；仅当监督器确认进程已终止且其声明的缓存目录已清空（cgroup 终止 + 目录清空为可验证依据），或受控缓存完成可验证清理后，才从清理等待集合移除；无法确认者记录为"待核验副本"，不宣布全副本清理完成；读取禁用不等待清理。

## 4. 核心契约

### 4.1 Event 信封（合规 CloudEvents 1.0 线格式）

`specversion`、`id`（字符集不含逗号）、`source`、`type`（只带大版本）、`subject`、`time`（业务时间）、`dataschema`（URI）、`datacontenttype`；扩展（纯小写字母数字标量）：`emittedat`、`traceparent`、`runid`、`mode`（live/replay/shadow/eval/backfill）、`partitionkey`、`subjectseq`（字符串编码 64 位，**仅 causal 键**）、`expiresat`、`hops`、`tenantid`、`domainpack`、`actortype/actorid/actorobo`、`impl`、`dataclass`、`publicationpolicy`、`causedby`（逗号分隔上限 32，完整父关系落血缘表）、`attr<name>`（注册别名，只允许声明为可路由的属性）；载荷 `data` 内联（\<16KB）或 `dataref + datadigest`（RFC 8785）；**来源内容载荷一律 **`dataref`。SDK 显式映射与序列化一致性测试。

### 4.2 Claim

`subject` 结构化（文档、实体、属性）；`claim_type`：extraction / statistic / decision / inference / forecast；`revision` + `content_digest`；双时态；四类证据（span / claim / query / rule）；**quote 规则**：模型只出 quote 与上下文，框架定位，短 quote 提高消歧要求，歧义 → `contains_ambiguous_reference`，归一化匹配不标精确，cleaner 保存区间映射，偏移为 Unicode 码点。  
**引用检查**（计算段）：证据存在、哈希一致、quote 匹配；**逻辑证据的种类与生产者满足该 claim\_type 要求**（extraction 的 span 只能指来源内容；Agent 中间物不得作 span 目标）；**证据落在本任务输入集合的血缘闭包内；extraction 的 span 必须属于 **`subject.doc`** 所指文档；逻辑证据的来源与 Claim 声明的文档/范围匹配**，不只检查正文相同。  
**质量语义**：`method`；`flags`（含未核验模型输入、含模拟输入、来源已撤回、含歧义引用、含推断关系）沿链传递；不设统一可信等级，展示为方法徽标 + 验证结果 + 依赖标志；放行由版本化 `acceptance_policy` 决定；人工复核只作用于被复核那条。ValidationRecord 绑定 `content_digest`，六维按同步/异步/不适用，computation 维含 `affected_by_deletion`；激活发 `claim.accepted`。ReviewRecord（复核文本不贴原文）。EvaluationRecord 不可变；n=0 显示"评价未知，按策略抽检"；n\<30 带区间。`status`** 五态**：`candidate`（已提交未放行）/ `active`（放行并发 `claim.accepted`）/ `superseded`（被同主体新修订取代）/ `withdrawn`（显式撤回命令）/ `rejected`（校验或复核不通过）；只允许 candidate→active|rejected|superseded|withdrawn、active→superseded|withdrawn（candidate→superseded **仅在同主体更新修订被放行为 active 时发生**；新修订仅进入候选时旧候选保持 candidate，新修订被拒后旧候选仍可放行）；**来源删除只设 **`flags.source_withdrawn`**（任何状态均可设，读时生效），不改 **`status`**；**`withdrawn`** 只用于显式撤回命令**；遮蔽用遮蔽记录不生成新修订。CI 枚举每对状态的可达性（含"新修订被拒后旧候选仍可放行"）。实体与话题 ID 只增不删，合并带 epoch。

### 4.3 Evidence 与标准文档

**EvidenceRef 标识不可变的逻辑证据对象**。**身份摘要只覆盖不可变出处**：租户、`kind`（source\_content / model\_output / statistic / rule\_decision / agent\_intermediate / raw\_response）、来源身份与修订、`producer`（平台授予的服务身份）、父证据、正文摘要、采集时适用的合规清单版本。**数据分级、保留类别、访问范围为可变治理属性**，以 EvidenceRef 为键单独版本化存储并留变更审计，变更不改变身份，重新分级不触发删除扇出；访问检查读当前治理属性。URI 形式 `evd://sha256:<digest>`，**摘要计算对象为逻辑证据清单**。

**blob 按字节摘要去重，范围限同一租户**：两个正文相同的帖子或恰好等于原文的模型输出可共享字节，不共享来源元数据。**删除作用于逻辑证据对象**：撤回后该 EvidenceRef 立即不可读（控制对象行事务只建立禁读与写屏障、登记清理责任）；**证据层扇出处理器**在自己的事务内、以首次撤回状态转换为条件幂等地写入正式持有的流水 −1。**引用记账以"引用持有者"为单位**（逻辑证据身份由内容推导，同一对象会被多个任务、多个作业抓到，因此不能按对象计数），持有者分两类。**① 暂存持有**，键为（任务 ID，逻辑对象 ID）——**凡在提交事务之外创建的逻辑证据对象一律经暂存登记**：`raw_response` 由连接器进程组登记，模型输出由网关服务端在调用返回时登记，Agent 中间物经证据 API 登记；写入方在同一个独立事务内创建对象（状态 staged）并为发起任务写暂存持有 +1（持 blob 行 KEY SHARE），同一任务重复登记幂等。**登记事务必须首先按全局锁序对任务行取 **`FOR UPDATE`**，复核任务非终态、当前租约与 fencing 代次（采集任务同时复核当前执行责任与 **`job_generation`**）**，再取控制对象行与 blob 行锁，原子登记逻辑对象与暂存持有；任务进入**任何终态**（completed、completed\_violation、死信、cancelled、skipped 等）时，终态事务持同一任务行锁，原子完成终态转换与该任务全部暂存持有的释放（−1），不论对象是否已转正，此步不取 blob 锁；终态先提交时后续登记请求不得新增或恢复暂存持有（既有登记可返回原回执），登记先提交时终态释放必涵盖该登记。**对象首次转为 withdrawn 时，扇出处理器在同一事务内为该对象全部未释放的暂存持有写 −1**（唯一约束保证与终态释放不重复），不必等任务终态。**所有 −1 写入**（任务终态释放、撤回时释放暂存持有、正式持有撤回）一律以 `INSERT … ON CONFLICT DO NOTHING` 写入；**一个事务写多条流水时按统一的持有关系键顺序执行**（唯一索引的隐式等待不在显式行锁的无环论证之内，排序后不会形成唯一键等待环；数据库死锁仍按整事务回滚、幂等重试处理）。**② 正式持有**，键为逻辑对象 ID——**只有在提交事务内首次创建的种类**（**来源内容**——normalizer 在其 complete 内创建的规范化正文、统计结果、规则决策）在第 ⑧ 步直接写正式持有 +1；已 staged 的对象在转正时写正式持有 +1（`raw_response` 在采集 complete 转正时、模型输出与中间物在提交段第 ⑧ 步转正时），以 `INSERT … ON CONFLICT DO NOTHING` 写入并持 blob 行 KEY SHARE 校验实例为 live；已存在正式持有时再次转正为无操作；正式对象撤回时由扇出处理器以首次撤回转换为条件写 −1。**流水唯一约束**：（持有者类型，持有者 ID，逻辑对象 ID，方向）。**逻辑对象记录当前绑定实例**：暂存登记时若对象已存在、没有正式持有、且绑定实例已被 condemned，则在持有新 live 实例 KEY SHARE 的同一事务内以条件更新改绑（并发改绑时由部分唯一索引保证复用同一 live 实例）；有正式持有或有效暂存持有的对象其绑定实例引用数 ≥ 1、不会被回收，因此不改绑；**每个持有者的 −1 写在它 +1 所在的实例上**（按 +1 流水查得），不取对象当前绑定实例。**逻辑对象状态机**：staged → formal | withdrawn；formal → withdrawn；withdrawn 为终态；staged 期间命中删除只改状态、不写正式流水；转正以条件更新执行，对象已 withdrawn 时按屏障剔除，已 formal 时无操作。**不设独立的孤儿清理作业**：没有任何持有者的 staged 对象可被新任务再次暂存并照常转正。`retry_after(blob_condemned)` 只会出现在提交事务内首次创建的种类上，由该种类的写入方重新上传；经暂存登记的对象转正时暂存持有保证引用计数 ≥ 1。

**blob 行主键 =（租户，字节摘要，实例 ID）**，**三态 **`pending | live | condemned`，同一摘要下至多一个 `pending` 或 `live` 实例（以（租户，摘要）上条件为 pending 或 live 的部分唯一索引保证）。**上传三步**：① 独立事务插入 `pending` 实例行并提交——插入冲突时不上传：已有实例是 live 直接复用，是 pending 则等它变为 live 后复用，它超时被回收则从 ① 重来；② 以实例 ID 为对象存储键写入字节并确认持久；③ 条件更新 `pending → live`，命中 0 行（实例已被回收）时上传方放弃该实例、从 ① 重来。**持有流水（暂存 +1 与正式 +1）只能写在 live 实例上**；对象存储中不存在没有实例行的字节（实例行先于字节）。**字节写入受实例状态约束，迟到写入不得留下可读字节**：Demo 的字节存放在 PG，第 ② 步在短事务内对实例行取 KEY SHARE 并确认仍为 pending 后写入，实例已 condemned 则写入失败，与回收互斥；生产档对象存储**写入凭证一律限时**（有效期不超过上传时限），每个实例使用独立数据密钥、上传前加密；回收时机按存储策略计算 `reclaim_not_before`——PG 互斥方案与独立密钥方案为上传时限（独立密钥方案回收时销毁密钥，迟到落地的密文立即不可读），无独立密钥方案不得早于"凭证失效时间 + 适配器能够证明的**服务端**单次写入最长耗时"（不得用客户端请求超时替代）；零引用 live 实例若仍可能有在途写入同样受此下界约束；存储策略与服务端写入耗时上界在存储适配器能力声明中登记；适配器须提供在途写入终止确认或持续清理对账能力，不得跨网络上传期间持有 PG 行锁。**实例进入 condemned 后禁止启动新写入且持久化字节清理责任**：清理责任只在所有已登记的在途写入完成或被可验证终止、且最终删除确认后才结束（**凭证失效时间 + 服务端单次写入最长耗时之后即视为在途写入已可验证终止**，此后做最后一次删除并确认即闭合——独立密钥模式同样适用，避免无限期对账）；迟到写入完成回调或第 ③ 步失败必须幂等重入该实例的清理队列；不能证明写入已静止的实例持续对账、不宣布字节清理完成；condemned 不得恢复为 live。**上传与等待一律在登记事务之前完成**：登记事务内若发现实例不是 live 就回滚，在事务外完成上传后重试（不在持任务行锁的事务内等待他人的 pending）。改绑与 `retry_after(blob_condemned)` 后的重新上传都沿用三步。引用流水绑定实例 ID，以只增流水（+1 / −1 记录）维护，不在热行上原地更新；流水归档保存"归档基数 + 连续归档前沿"，最终引用数 = 归档基数 + 前沿之后的流水，不得只汇总活动流水。**回收作业**（Read Committed）回收两类实例：引用汇总为 0 且超过宽限期的 live 实例，以及到达 `reclaim_not_before` 仍为 pending 的实例（无论字节是否写成）——先对 blob 行取 `FOR UPDATE`，再以独立语句重新汇总已提交流水（不得使用取锁前的候选汇总或等待锁期间建立的快照），条件满足才在持锁期间置为 `condemned`，**置 condemned 后立即提交事务释放锁**；字节删除（生产档为销毁该 blob 实例的独立密钥）在事务外异步执行，失败可重试，以实例 ID 幂等，不在持锁期间访问对象存储。新建逻辑对象只允许引用 `live` 实例（提交段对 blob 行取 `KEY SHARE`，所有 +1 路径都必须持有该锁）；提交段发现目标实例已 `condemned` 时整包返回 `retry_after(reason=blob_condemned)`，不计失败，SDK 重新上传生成新实例后以同一结果包重提——逻辑证据身份不含实例 ID，`semantic_bundle_digest` 不变，回执幂等不受影响。清理完成判据中的"证据层完成"指逻辑对象已撤回、引用流水已写入，不要求仍被其他有效对象引用的 blob 被删除。CI：回收作业与同正文新帖并发提交，新帖可读；等待回收锁期间提交新引用后回收不得删字节；流水归档后回收正确；相同摘要不同实例；重复清理幂等；回收中崩溃不留半删除状态；staged 期间被删且任务终态后净值为 0；T1 违规结局、T2 转正同一对象，字节保留；暂存释放、实例被回收后重采，对象改绑新实例，转正后可读；旧持有者的 −1 落在旧实例上；两个任务并发改绑只产生一个 live 实例；两个任务并发首次转正只写一次正式 +1；staged → 转正 → 撤回净值为 0；模型输出写入后任务重试超过宽限期，字节仍保留；staged 对象被删时所属任务仍在退避中，字节照常回收；登记先提交 / 终态先提交、登记请求延迟、旧租约登记、登记事务回滚四种交错均不留无责任持有；死信终态释放暂存持有；登记提交后 complete 回滚，staged 与暂存 +1 均保留；字节删除缓慢时撤回登记不受阻；上传第 ① 步后崩溃 / 第 ② 步后崩溃 / 登记因任务已终态被拒 / 网关登记时任务已取消 / 两任务并发上传同一摘要——五种情况回收作业都能找回字节且对象存储无无行字节；pending → 上传在途 → 超时 condemned → 删除成功 → 迟到上传落地 → ③ 失败：Demo 档写入被拒、生产档密文不可解密且最终字节仍被清除；迟到回调丢失、清理器重启、重复删除均收敛；独立密钥模式下迟到回调丢失、凭证到期后清理责任闭合；两种存储策略的回收边界；超时请求在服务端继续执行；终态释放与批量撤回交错回滚后净值、重复释放与重试收敛。

**墓碑**：源 ID 含作者派生身份时只存键控哈希；含对象范围（文档 / 账号 / 来源）、原因、确认依据、来源版本/位置、观察时间。

### 4.7 Worker 协议

```
lease(consumer, max_tasks)                       -> [task{..., key_epoch, pinned_versions, context, last_committed_segment, checkpoint, retry_after?}]
heartbeat(task_id, lease_token)
checkpoint(task_id, lease_token, segment_no, partial_bundle) -> segment_receipt | conflict | unsupported
complete(task_id, lease_token, bundle, after_segment)        -> receipt | rejected(reason) | conflict | retry_after
fail(task_id, lease_token, error_class, retryable)
```

**确定性 ID 派生**（SDK 统一函数）：`H(task_id, segment_no, output_kind, local_output_index)`；同段重传不变，不同段、不同对象类型不碰撞；已有对象引用与修订不适用新 ID 派生。**Event ID、Claim ID 与被引用稳定身份纳入摘要**；"新分配主键"排除项仅指数据库内部代理键。

**计算段（运行时侧；事务外执行、不等待远端模型/API、不做无界重算）**：确定性校验（结构、引用检查含种类/生产者/来源/血缘闭包核对、范围、枚举、槽位外文本扫描、query digest 重放）、血缘与证据引用核对；产出校验材料，由运行时密钥（Demo HMAC）签名，绑定 `semantic_bundle_digest`、操作类型、任务、segment、租约代次、配置锁、策略版本、输入快照、`pre_control_epochs`**（本包所涉文档与账号控制对象在计算时的撤回代次）**。材料区分**控制变更前提**（pre\_control\_epochs、本包携带的控制信号）与**变更后写入投影**（所有根来源处于永久撤回状态的条目及其依赖写入已被确定性剔除并记录，不论撤回来自本包还是外部；非采集包中被剔除的 Claim 记"输入已撤回"，全部输出都被剔除时任务以 `skipped_withdrawn` 结束）；控制信号与剔除记录均纳入摘要。**本文"控制信号"仅指 **`tombstones[]`** 与账号控制信号（永久撤回或临时原因）**；normalizer 的非撤回类控制记录与 Claim 撤回命令不属于控制信号。SDK 预跑不被信任。

`semantic_bundle_digest`：RFC 8785 规范化，覆盖 Claims、状态写、外发事件、`derived_writes[]`、检查点推进、原始响应转正、PageResult、规范化任务、续采任务、覆盖声明、**删除与账号控制信号**、`publication_policy`；引用对象纳入稳定身份 + 版本 + 内容摘要；排除白名单：数据库内部代理键、receipt ID、非语义时间戳、lease token、heartbeat；逐字段 `digest: include|exclude`；最终 complete 覆盖分段摘要列表。

**全局加锁顺序**：任务行 → 键占用行 → **控制对象行（文档、账号；按（范围类型，ID）统一排序；同一对象需要多种锁时一开始取得最强模式——仅引用 **`SELECT … FOR KEY SHARE`**；**永久撤回变更 `SELECT … FOR UPDATE`**（显式行锁，不以普通 UPDATE 隐含的 **`FOR NO KEY UPDATE`** 替代，后者不阻塞 KEY SHARE）；**临时原因变更 `FOR NO KEY UPDATE`**（临时原因不参与比对，不应阻塞持 KEY SHARE 的提交）；同一对象同时涉及两种变更取 **`FOR UPDATE`**；不得升级；来源范围不入锁序，见 4.12）** → **撤回日志计数行（单行 **`FOR UPDATE`**，仅含控制变更的包获取）** → **blob 行（按（租户，摘要，实例 ID）排序；引用取 KEY SHARE，回收取 FOR UPDATE）** → **逻辑对象行（按对象 ID 排序；转正、改绑、撤回取 FOR UPDATE）** → 状态行（按键排序）→ 序号计数器 → 作业/检查点行；计时器事务不得持作业锁再获取序列中更靠前的行。控制对象行以 `INSERT … ON CONFLICT DO NOTHING` 幂等创建后再按锁序加锁。staged 登记事务的顺序为任务行 → 控制对象行 → blob 行 → 逻辑对象行；扇出处理器只锁逻辑对象行；回收作业只锁 blob 行——三者与提交段不形成环。死锁按瞬态处理不计失败。CI 锁序断言测试。

**提交段（13 步）**：① 锁任务行；② 有序消费者锁本任务的键占用行；③ 先查分段回执与终态记录，**先区分普通完成与代次变更终结**：普通完成及分段回执按原摘要规则（同 digest 返回原 receipt，不同返回 conflict，SDK 不重试）；**任务已因代次变更终结**（第 ④ 步或第 ⑫ 步的旧代次受限投影，或扫尾）时，合法旧包进入**受限控制投影分支**，优先于普通摘要冲突判断——在当前已持任务行锁的事务内进行（不另开事务，避免等待自身持有的任务行锁），按第 ⑤ 步验签并核对绑定、校验控制契约与权限，按统一锁序幂等登记本包已通过校验的控制信号，不再改变终态、不释放持有、不修改键占用；投影回执以回执表的独立操作类别保存，按（任务 ID，租约代次，`semantic_bundle_digest`）幂等——同一投影重复提交返回原投影结局，同一任务不同的合法旧包（如前后两个租约各自取得的包）各自只接收控制信号、不接收普通业务输出；返回 `conflict(lease_lost)`，不触发当前作业结算——墓碑不因扫尾或先到的旧包而丢失）；④ 非终态复核当前租约持有者、代次、有效期（采集任务同时核对 `job_generation` 与代次变更栅栏：不匹配时——无论租约是否仍有效——走"旧代次受限投影"——只登记本包中已通过控制契约与权限校验的控制信号，任务按作业操作已登记的目标状态终结，投影回执按第 ③ 步的操作类别与幂等键登记，返回 `conflict(lease_lost)`，不触发周期结算；同一代次内的租约失效不做此登记，由新持有者从同一检查点重采），并核对 `after_segment == last_committed_segment`（否则 `segment_frontier_mismatch`，不产生任何写入）；⑤ 验签校验材料并核对绑定；⑥ 汇总本包引用及控制变更涉及的文档、账号控制对象，按统一顺序逐行加锁（仅引用 `FOR KEY SHARE`；仅临时原因变更 `FOR NO KEY UPDATE`；永久撤回或同时涉及两类变更 `FOR UPDATE`；同一对象预先取最强所需模式，不升级）；**先将锁内当前状态与材料绑定的 **`pre_control_epochs`** 比较（控制行不存在等价于"代次 0、未撤回"）**：`pre_control_epochs` **只绑定永久撤回代次**（临时原因的设置与清除只递增该行的 availability 版本，不递增撤回代次，提交时不比对）；若差异恰好是本包控制信号所要求的目标状态（同一对象已被他人置为相同的永久撤回），视为已应用、不判冲突；其他永久撤回代次差异 → `conflict(control_epoch_changed)`；本包携带的临时原因信号**带来源事件位置**（Jetstream 用事件时间或 seq，其他来源用来源声明的时间戳；没有可比较位置的来源在连接器 Manifest 中声明，按提交顺序应用），**临时原因的比较基准 **`comparison_basis`** 在来源配置锁中固定，不得逐对切换**（混合"同域用位点、跨域用时间"的比较器不具传递性，会形成比较环）：具备可信跨实例上游事件时间的来源，所有事件（含同位置域）统一按上游事件时间判定新旧，实例位点只用于续接与去重；不具备该能力的来源使用**单一权威位置域**（位置域 =（来源，生成该位置的上游实例）），切换位置域须经显式 `handoff_epoch` 建立 fencing，旧域迟到事件不改变状态；**非权威、也非旧域的位置域事件一律不改变状态、只做记录**，其中设置类事件按下述保守保持登记；建立 handoff\_epoch 时记录旧域最后已处理位置与新域起始位置，**无法证明两者之间无遗漏**（无位点映射，或映射未通过重叠验证）时对跟踪集合中的账号安排一次批量账号状态核对：核对复用下述保持的回访、预算与转人工机制，登记为**交接核对保持**——**登记时不把该原因置为"已设置"**（不新增禁读，避免整个来源的跟踪账号同时禁读），只阻止它在核对完成前被清除：核对期间该账号的清除类信号一律并入保持、不生效，设置类信号照常应用（并按下述规则并入），核对结果按回访规则生效；核对保持并入无法定序的冲突时转为保守保持；切换区间可能漏掉停用这一有界风险（只影响位置模式）在覆盖声明中披露；声明完全不可比较的来源按提交顺序应用**设置类**信号并披露该语义，**清除类信号一律经保守保持与回访生效**（否则清除可覆盖更新的设置，方向不保守），不与可比较模式逐事件混用。控制行按原因保存最近一次已处理的（比较基准，位置域，位置，上游事件时间）：比较键更旧的信号为无操作并在回执记"已被更新事件覆盖"；**位置更新的合法信号无论目标状态是否已满足都必须原子推进该原因的最近已处理位置**（位置推进本身不递增 availability 版本、不分配序号、不登记扇出，只有有效状态实际改变才执行这些动作；位置记录在原因解除后仍保留）；比较键相同时，仅上游事件身份（不采用不同任务派生的平台 Event ID）与目标均一致才视为重复；**无法定序的冲突一律登记到保守保持**：比较键相同或缺失而目标不同的信号（以及按提交顺序模式下的全部清除类信号、位置模式下非权威位置域的设置类信号），**不论先到的是设置还是清除、也不论目标状态是否已满足**，都登记到该（租户，账号，原因）**唯一一个未关闭的保持**（hold，含 hold\_id、类型（保守 / 交接核对）、并入的冲突列表、最后一次并入时刻）；同一原因同时至多一个未关闭保持，之后的无法定序冲突只并入、不另行安排回访；保守保持期间该原因按保守方向处于"已设置"。**保持未关闭期间生效的设置类信号**：比较键严格新于保持中全部冲突的，按正常规则应用并关闭该保持（在途回访结果随之作废）；不能如此证明的（按提交顺序模式下的设置类信号一律如此，交接核对保持期间的设置类信号亦然），在应用的同时并入该保持——更新最后并入时刻，观测为"未设置"的在途回访因此失效，能以"未设置"解除保持的回访必然晚于该设置（否则较早的回访观测会覆盖较新的设置；不采用"设置直接关闭保持"，以免丢弃保持中实际更晚的清除）。**保持的登记、并入、关闭与回访结果的写回都在该账号控制行的 **`FOR NO KEY UPDATE`** 锁内进行**，回访有效性在锁内按当时的最后并入时刻与保持状态重新判定（保持已关闭或 hold\_id 不符则结果作废）。**账号进入永久撤回时，在同一事务内关闭该账号全部未关闭的保持**（记"已被永久撤回覆盖"），并作废在途回访、核验预算与覆盖证明，不产生人工待办；永久撤回对象不再生成保持与回访。**每个保持至多一个在途账号状态回访**，唯一键（租户，命名空间，账号，原因，hold\_id）。**回访结果不按比较基准与事件比较，而按覆盖证明判定**：只有回访观测的可信新鲜性下界严格晚于**判定基准时刻**（若 handoff\_epoch 在其后建立，还须晚于 handoff 建立时刻），结果才有效：观测为"未设置"时，判定基准时刻为该保持最后一次并入时刻（含并入的设置类信号）；观测为"已设置"时，判定基准时刻为最后一次并入清除类信号或无法定序冲突的时刻——之后并入的设置类信号与该结论一致，不使它失效（避免持续到达的设置反复作废回访、耗尽预算）。有效结果把该原因置为回访所见状态并关闭保持，同时为该原因记录**覆盖前沿** `resolved_cover_at = 新鲜性下界 − 来源声明的上游时钟偏差上界`（来源未声明偏差上界则不记），之后上游事件时间不晚于覆盖前沿的事件为无操作；覆盖前沿单独保存，**不改写上游事件比较键**（不把平台观测时间冒充上游事件键）。**回访确认"已设置"后的清除资格**：覆盖前沿只能排除可证明已被覆盖的事件，不能证明其余事件晚于回访。因此有效回访以"已设置"关闭保持时，保留该回访的**覆盖证明**（观测新鲜性区间、证据引用与**参照时刻**——取回访观测保守上界与保持最后一次并入时刻中较晚者）：新的有效"已设置"回访替换旧证明，账号进入永久撤回时一并废弃，原因经有效途径转为未设置时退役；其间清除类信号只有能证明发生于参照时刻之后，才按比较基准正常应用。证明方式二选一：时间模式下"事件时间 − 上游时钟偏差上界"严格晚于参照时刻；或任一模式下"首次可信入口接收时刻 − `control_delivery_bound`"严格晚于参照时刻——接收时刻为受控传输层首次接收该事件时记录并持久保存的保守下界，不得使用入库、complete、补偿、重试或再次导入的时刻，重收与重试不使其后移；`control_delivery_bound` 须为 guarantee、明确覆盖该类账号控制事件、端点为"上游实际发生至本平台受控传输入口首次接收"，只约束源端可见性、其他事件类型或经验 SLA 的保证不得使用，不满足即禁用该证明方式；**接收时刻证明只用于实时送达的事件**——首次接收发生在断线重连追赶、游标回放、resync 补采或实例切换衔接区间内的事件（受控传输层为其打追赶标记：自重连或回放开始，直到连接器确认追上实时位点为止，无法确认则整段按追赶处理）不得使用该证明，改走事件时间证明或保守保持；恰等于参照时刻不算通过；不能证明的清除登记或并入保守保持、经回访生效，不得仅因比较键大于原已处理键就清除原因。回访确认"未设置"时不保留此约束（设置类为保守方向，照常应用）。结果无效或无法确定新鲜性下界时只记 unresolved，**不再生成新保持或新回访**；后续尝试由持久化的核验预算与退避计时器驱动，成功抓取但未解决不重置预算；预算耗尽保持保守状态、告警并转人工处理，不暂停主采集作业。回访绑定 hold\_id、handoff\_epoch 与已处理前沿，不覆盖其后到达的新事件：比较键严格新于保持中全部冲突的清除类事件同样按正常规则应用并关闭该保持（交接核对保持除外：核对完成前清除一律并入），仍无法定序的并入同一保持。保守保持不判 V19（这是第 ⑥ **提交结局**：① 外层结果包无法解析、鉴权失败或完整性失败 → 整包 `rejected`，SDK 不重试，任务进死信；② **采集任务外层合法且 FetchPage 可安全解码时，其字段组合（含未知 status 值）由 4.11 采集合法性校验分类，违规走"违规结局"（受限提交投影，任务 **`completed_violation`**，作业转 paused），不进死信**；③ 单条 Claim `rejected / review_required` → 任务仍可 completed，该条不触发正式下游（`claim.accepted` 不发）；④ `conflict(reason)` 不计业务失败，原因枚举：`digest_mismatch`（同任务不同摘要，SDK 不重试）、`lease_lost`（SDK 放弃该任务，由新持有者重做）、`control_epoch_changed`（运行时在同一事务内**保留租约**并返回最新永久撤回代次，持有者以新前提重新计算后再提交；永久撤回单调、每对象至多一次，故一个包的重算次数不超过它涉及的控制对象数，**不消耗尝试预算、不进死信**）、`state_version_changed`（状态期望版本不匹配：不提交业务写入，保留租约，返回最新状态版本，持有者重新读取状态并计算；计入版本化的冲突重算预算，超限按瞬态失败处理）、`segment_frontier_mismatch`（SDK 重新 lease 以取得最新分段前沿）；`lease_lost` 含任务租约失效、键级 fencing 代次失效、采集作业 `job_generation` 或代次变更栅栏 CAS 失败，以及仅检查点版本冲突（诊断明细 `checkpoint_version_changed`；运行时已撤销租约并将任务退回排队、保留原位次，旧租约的 heartbeat 与 complete 均被拒）；⑤ `retry_after(reason)` 不计失败，原因枚举：`pg_admission`（PG 准入，6.3）、`blob_condemned`（4.3）。**fail 三结局**：可重试 → 按预算重试保留原位次；不可重试 → 死信；输入已撤回 → `skipped_withdrawn`。**采集任务的任何终态都调用作业责任结算**（4.11）。CI 对比"未知 status"与"损坏 bundle"，验证终态及允许写入集合不同；纯删除包、创建后删除折叠、控制变更同时带其他条目、外部撤回并发、重复控制包同回执；两包携带同一删除先后提交只产生一条撤回日志、一次代次变化且后者不判冲突；预墓碑与 staged 登记并发创建控制行不判冲突；control\_epoch\_changed 后同一持有者以新前提重提成功；账号停用 / 恢复反复切换时引用该账号内容的提交不冲突；N 个对象依次被外部撤回，重算次数不超过 N 且作业不暂停；采集包计算后提交前一条帖子被外部删除，重算后该条被剔除、其余正常转正；状态版本冲突、键级代次失效、重算中状态再次变化。**批量 complete**：跨键逐任务原子；同键成功前缀逐任务提交（语义与测试定义；Demo `max_batch=1`，批量实现列 Phase 2-A）。

#### 4.7.1 外发箱发布

SKIP LOCKED 只认领桶；每桶一个活跃转发器（桶租约 + 代次，确认为桶代次、租约、队头身份的 CAS）；**causal 键**：每键仅发布最早未确认项，按 `subjectseq`；**arrival 键**：同分区流水发送，**按逐项 ACK 或连续已 ACK 前缀持久化确认**，不因 ACK 回调顺序把已成功的后项当失败；生产者固定 `enable.idempotence=true, acks=all, retries>0, max.in.flight≤5` 并启动校验；出错即停桶重建生产者从最早未确认继续；Kafka 确认后才标已发布；故障接管允许重复，下游按事件身份去重（保序承诺 = 不同事件的首次有效物化与处理保序）；桶配置版本化；Demo 固定桶数、单转发器（多转发器列 Phase 2-A）。

#### 4.7.2 采集提交

原始响应在 complete **之前**经独立登记事务写入 staged 对象、暂存持有流水 +1（持 blob 行 KEY SHARE）、屏障与删除责任登记，该事务不随 complete 回滚。采集 complete 的短事务原子写入：既有 staged 对象转正（首次转正写正式持有 +1，已有正式持有则无操作）、PageResult、规范化任务、续采/恢复任务、覆盖声明、检查点（`checkpoint_advance = {job_id, job_generation, cycle_id, expected_checkpoint_version, next_checkpoint, page_result_ref, coverage_ref}`）、**删除事件与账号控制信号统一按提交段第 ⑥ 步的同一控制状态转换函数处理（永久撤回状态首次改变时递增永久撤回代次；临时原因的设置与清除只递增 availability 版本；目标状态已达成时不递增版本、不重复分配日志序号或登记扇出责任）；"快速通道"仅表示控制信号不以目标正文可读为前提，不构成第二套状态更新协议**。检查点只在控制帧的处理在同一 complete 内提交后才推进过该帧。标准文档在 normalizer 独立 complete 中提交；normalizer 不产生墓碑。检查点含义是"原始数据与处理责任已可靠接收"。

### 4.11 采集作业

作业身份稳定；`job_generation` 随查询版本、凭据范围、窗口、模式、游标语义不兼容的连接器升级递增；检查点绑定代次；领取时原子检查 `job_generation`、作业状态（periodic 另检查 `cycle_id`；continuous 不以 `cycle_id` 作领取校验），读检查点，提交时 CAS。作业显式声明 `execution_form: bounded_slice | long_session` 与 `continuity: required | best_effort`（缺省 best\_effort）（计划解析校验：`long_session` 要求平台 `worker_checkpoint`；`bounded_slice` 不因 `continuous` 调度要求 checkpoint；连接器 `supports_resume=false` 不得以 `bounded_slice` 执行 `continuous` 作业；`continuity=required` 时核对连接器的恢复能力声明，不满足即拒绝，`best_effort` 按明确的缺口 / resync 策略运行）。**作业状态机**：idle / running / cooling / paused；周期计时器只在 idle 触发；冷却恢复计时器在 cooling 生效，**恢复身份绑定本次冷却代次或触发 PageResult**（旧计时器不误触发）；周期、续采、恢复任务各有稳定身份。**周期（cycle）定义**：periodic 为一次计时器触发到作业回到 idle。continuous 为来源配置中的固定时间窗（缺省 1 小时，版本化）：`cycle_id` 只用于恢复预算记账与周期成功判定，不作为切片任务的领取校验条件；切片任务身份为 `(job, job_generation, slice_seq)`，`slice_seq` 在作业代次内单调递增、跨窗口不重置；`cycle_has_success` 的成立条件为"合法性 verdict 为 valid 且 FetchPage.status 为 ok"（空的正常切片也成立；非 ok PageResult 的成功登记不设置此标志），窗口内成功只设置标志，不提前关闭周期；**周期在窗口边界结算**——边界后的**第一次任何当前代次作业级事务**（切片成功、限流或传输错误登记、违规结局的受限投影、恢复任务结束、死信登记、显式恢复——显式恢复先完成旧周期结算再建新周期并重置预算）在持作业行锁的同一事务内先检查窗口边界：若已跨窗，先依据旧周期保存的标志完成结算（有成功 → 重置恢复预算；空窗口 → 预算延续，即把旧 `cycle_id` 的已用余额结转入新 `cycle_id` 记录，`cycle_id` 只是记账分区而非重置边界），再建立新周期，最后把本次结果记入新周期；跨越多个窗口时按顺序逐窗结算；结算以 `current_cycle_id` 的 CAS 保证同一边界只结算一次；**作业代次变更（升级、替代、显式作业操作）协议**（同一作业同时至多一个未完成的代次变更操作，后到者等前一个完成后再登记栅栏；操作记录以（job\_id，旧代次）唯一）：① 以独立短事务在作业行登记栅栏、`operation_id` 与该旧代次的**默认终结目标**；**栅栏同时拦截领取与新建**——凡为该作业新建任务的事务（提交段的续采与下一切片任务、恢复计时器、周期计时器、显式恢复）都必须**对作业行取 **`FOR NO KEY UPDATE`** 锁，在锁内复核预期 **`job_generation`**、未完成代次变更栅栏与允许的作业状态，并持锁至创建事务提交**；复核失败即回滚拟新建任务；不得以普通 SELECT、事务外预检查或只检查"当前无栅栏"替代（提交段的续采与下一切片任务在第 ⑫ 步同一事务内创建，已持作业行锁；计时器与显式恢复按"新建任务行 → 作业行"的锁序；新插入的任务行在提交前对其他事务不可见，不构成锁序反向；不用 `FOR SHARE`，以免创建事务随后更新作业行时锁升级）。栅栏登记与代次更新对作业行的更新与该锁互斥，因此任一新建事务要么先提交（其任务在第 ② 步扫描中可见并被绑定终结目标），要么见到栅栏而回滚；栅栏事务不得持作业锁再取任务锁；**栅栏登记后，旧代次任务的 heartbeat 不再续租并返回停止指示**（worker 尽快提交已抓取部分），在途任务因此最迟一个租约周期内提交或租约失效；② 栅栏提交后按 task\_id 升序锁定旧代次**全部非终态任务行**（排队中与已领取的）并为每个任务幂等绑定终结目标（首次绑定后不可覆盖）；③ 同一事务内更新作业代次、使旧恢复计时器失效，并统计旧代次非终态任务数；④ **扫尾**：由 operation\_id 驱动的扫尾器在代次更新提交后，按已绑定的（未绑定的取默认）终结目标终结**未被领取或租约已失效**的旧代次非终态任务（不依赖这些任务自己调用 complete）；**租约仍有效的在途任务不终结**，等它自己提交（走受限投影）或租约失效后再终结——之后迟到的 complete 仍按提交段第 ③ 步登记控制信号；发现未在第 ② 步绑定终结目标的旧代次任务（扫描后出生）时同样终结，并告警、按 operation\_id 审计定位绕过了作业行锁内复核的新建路径（作业行锁内复核之下，正常并发不会产生此类任务）；全部旧代次任务进入终态后操作才完成（以数据库可用、扫尾器持续运行为前提，最多推迟一个租约周期）；任一阶段崩溃由 operation\_id 恢复，继续同一操作且不覆盖已登记的目标。第 ④ 步的代次核对为**预检查**；提交时作业行 CAS 同时校验 `job_generation`、栅栏与 `expected_checkpoint_version` 作为最终拦截，`checkpoint_advance.cycle_id` 只作记账来源（不得由定时器直接使在途任务失效）；代次不匹配走旧代次受限投影并返回 `conflict(lease_lost)`，该任务不重做，按作业操作已登记的目标状态终结，不触发周期结算；`long_session` 在分段边界结算。预算耗尽 → paused，**日历翻窗不隐式解除 paused**，显式恢复建立新周期并重置预算（记录授权）。**采集任务的任何终态一律调用作业责任结算**：① 决策表判定契约违规 → 提交段按"违规结局"提交**受限投影**：仅写入标 violation 的 PageResult（含全部违规码）、作业 running → paused、连接器健康状态、任务终态 `completed_violation` 与回执；本页 items 不转正、不生成规范化或续采任务、检查点不推进，staged 对象的暂存持有随任务终态释放（终态事务内写 −1）；**本页 **`tombstones[]`** 与账号控制信号在独立通过控制契约与权限校验后仍按快速通道登记**（保守方向：控制信号不以页面合法为前提）；不进死信；② 采集任务进入死信（fail 不可重试、尝试预算耗尽、外层结果包结构违规）→ 运行时在登记死信的同一事务内将作业 running → paused 并记录原因与告警；③ 对仍属当前 `job_generation`、当前执行责任的其他非成功终态：`skipped_withdrawn` 与背压 shed 产生的 `skipped` 结算为 running → idle 并按调度类型挂计时器（periodic 挂周期计时器，continuous 挂连接计时器；"没事可做"不是故障）；`cancelled` 与非预期的 `skipped` 同事务内解除执行责任并转 paused、记录原因；由升级、替代或显式作业操作产生的旧代次任务终结，按该操作已登记的目标状态结算，不得反向暂停新代次作业；④ paused 只经显式恢复命令解除，恢复任务身份绑定新的恢复代次。

null，completeness 有有效前缀为 partial、否则为 unknown。**多资源页的条目结果**：平台报告不存在或请求了却未返回的条目记 `missing`。**缺失观测的计数**（多资源页的 missing 与单资源请求的 gone × item 适用同一规则）：新鲜性下界已知时，**只有该下界严格晚于该文档的 **`last_presence_upper_at`** 即失效。`last_presence_upper_at` = 所有有效存在证据的快照时刻**保守上界**之 max（缓存 present 取来源响应时刻，不取平台处理时刻；可靠流事件取事件时刻上界加声明的时钟误差；单调不降，后到的陈旧 present 不降低它）——两个新鲜性下界相比不能证明观测先后，必须证明"缺失最早可能时刻晚于存在最晚可能时刻"。**present 只经抬高 **`last_presence_upper_at`** 打断计数**：抬高后，已计入且新鲜性下界不晚于新上界的缺失观测失效，计数随之重算；上界早于已计入缺失下界的陈旧 present 不打断计数（否则迟到的旧缓存会无限推迟真实删除的确认）；在 resync 清扫中 missing 视为"未通过核验"；`failed`（请求错误、超时）只计入"不可采"计数（同一条目连续 N 次登记为不可采并在覆盖中披露），不计入删除确认；`present` 只表示本次响应返回该条目，先登记"存在观测"（`observation_epoch`）；每条存在观测记录 `observed_at` 与观测时来源 / 账号的门控代次；**逐文档核验记录按门控范围分别保存**：`verified_epoch[source]` 与来源缺口代次比较，`verified_epoch[account]` 与账号 sync 代次比较，互不替代。每个核验代次 g 记录 `verification_cut_at(g)`——本次恢复需要核验到的可靠边界（可靠增量路径重新衔接的时点），**不采用缺失区间起点**；`verification_basis` 必须给出响应数据新鲜性下界（仅有最大陈旧时间 τ 时，下界 = `observed_at − τ`），**对存在观测路径 (a)，只有下界 ≥ verification\_cut\_at(g) 且其他依据检查通过，才推进 **`verified_epoch[该范围] := max(·, g)`；可靠增量路径 (b) 按 4.12 独立检查排序域与严格晚于 cut 的位点；一次观测未通过路径 (a) 不撤销已成立的其他核验证明，两条路径均不成立时才保持未核验；无法确定下界的存在观测不推进；cut `verified_epoch[范围]`，不依据本次请求代次或 present 本身（重复 present 不推进；旧核验不解除新缺口）。页内 missing / failed 均不改变页 status。来源配置声明 missing 的可能原因（如公开 AppView 对限制未登录访问账号不可见）；确认后一律按永久撤回处理（保守方向），墓碑原因记"来源不可见"。**"可安全解码"指 JSON 结构完整、必填字段存在、字段类型正确，不校验枚举取值**（枚举外取值由合法性校验分类为 V1）。**尚未形成 FetchPage 的进程 / 执行失败走 **`fail`**，不进决策表**。

**完备性测试**：CI 对（调度类型 × status 含 status\_reason / failure\_scope × completeness × end\_reason × 是否 continuation × 是否有效前缀 × 是否单资源 × item\_outcomes {空 / 观测集合内仅 present 或 failed / 观测集合内含 missing / 超出观测集合（再分含不含 missing）} × 请求方式 {按条目寻址 / 按查询或流}（单资源请求必然按条目寻址，"单资源 × 按查询或流"为不可达上下文，列为排除项不赋 verdict，CI 断言运行时不会构造出该组合）× 控制信号校验通过与否，每个枚举字段另加一个"未知值"取值，`status_reason` 另加"自由文本"取值）全组合分别计算 verdict、violation\_codes、动作表匹配行数、最终动作，断言：`valid` 组合动作表恰好一行且不在任何违规条目中；`violation` 组合至少一条违规码、primary 唯一确定、最终动作为违规结局且不执行任何动作行。**全组合断言只在 **`execution_form = bounded_slice`** 上执行**（Demo 平台 long\_session 在计划解析层拒绝，long\_session 特有组合随 Phase 2-A 启用时补表与补清单）。新枚举值合并时 CI 强制补表或补清单；CI 同时输出每个违规组合命中的全部条目供审阅。

**有界任务**：一任务 = 一页或一个有请求数/消息数/解压字节/耗时/页数上限的切片；评论树子作业身份 = (父作业, 帖子键)，根作业总扇出预算（余力）。

**fetch\_mode**：所有抓取模式下采集 Task/Event/Run 均为 live。`history`：经授权历史补采，产出沿链传播 `publication_policy: manual_only`，扇入时与普通输入混合不自动解除。`revisit`：渐长间隔重访，产出互动观测、`doc.updated`、`doc.deleted`、`doc.exited_query`。`probe`：ProbeRun（查询、入口类型、重复采样编号、请求配置摘要、参数、语言地区、上下文、会话状态、时间、回答、引用、响应状态、原始证据引用、产品版本线索、缓存信息；Phase 2-B，只经 API 测量）。`backfill` 执行模式专用既有数据内部补算。连接器 shadow 只读既有原始响应。采集任务不参与回放。

**边缘过滤**：不匹配查询模板的内容在内存过滤不落证据；跟踪集合含正式对象、staged 对象、本批次已选对象，其 update / delete / 账号控制事件必须处理；更新后不匹配记新修订或 `doc.exited_query`；同切片 create 后 delete 按原生顺序折叠：折叠只抑制本切片的 create，对应 delete 仍按键控哈希身份在正式对象与 staged 对象集合中查找，命中则登记墓碑，未命中才忽略；删除事件按键控哈希身份查找；覆盖声明记过滤规则版本、接收量、丢弃计数。

**抽样区分**：概率抽样可加权；配额抽样、接口截断、负载裁剪只报观测量。

### 4.12 删除义务（贯穿规则）

**控制对象（文档 / 账号 / 来源）**——全文统一用此名。每个控制对象有稳定控制行（含撤回代次与 availability 状态），以 `INSERT … ON CONFLICT DO NOTHING` 幂等创建；**允许由删除信号先行创建（预墓碑）**，删除先于创建到达时后到的 staged 转正被屏障拒绝；账号删除后晚到文档受账号控制行约束。**永久撤回与临时不可用分开**：永久墓碑不解除；临时不可用**按原因分别登记**——账号至少含 `account_inactive`（停用 / 封禁）与 `sync_unverified(sync_epoch)`（仓库重置待核验），来源为 `source_gap(gap_epoch)`（断流待核验）；有效 availability 由永久墓碑与仍有效的临时原因共同计算；**每种原因只能由对应事件解除**：账号恢复仅清除 `account_inactive`，sync 清扫完成仅在恢复代次匹配时清除对应的 `sync_unverified`，不得清除其他原因或永久墓碑；旧代次回执不得解除新代次门控。账号级 `sync_unverified` 的解除条件：**文档集合固定为 sync 帧到达时该账号已存的文档**（之后新抓到的不阻塞解除），每篇均处于"已按本代次核验 / 已永久撤回 / 已登记不可采"三者之一，尚未尝试或 failed 未满 N 次的文档阻塞解除；"已登记不可采"的文档不满足逐文档可读条件，自然继续禁读，无需另设原因。**有效 availability = 永久墓碑 ∪ 仍然有效的临时原因 ∪ 逐文档可读条件不满足**。清扫尚未上线期间只建立门控，不解除。**两种处置**：文档与账号范围的永久撤回走写屏障；来源范围的临时不可用只做读时门控（见下）。

**写屏障只针对永久撤回对象（文档与账号范围）**，覆盖全部写入通道：complete、staged 初次登记与转正、模型输出写入、缓存填充、**派生索引写入**（只允许经结果包 `derived_writes[]` 或声明了屏障的门面 API）。每次内容写入核对其全部根来源的文档控制行与作者账号控制行，按（范围类型，ID）统一排序取 KEY SHARE，校验材料绑定这两类代次；CI 检查扇出登记表中有删除处理器的存储，其所有写入 API 必须执行屏障。删除事务对控制行 UPDATE，只更新永久撤回状态、递增撤回代次、登记扇出责任，不反向锁任务与派生对象；**按目标状态幂等：目标状态已达成则无操作**（不递增代次、不分配序号、不重复登记）；临时原因的设置与清除只递增 availability 版本，不递增撤回代次。**来源范围只做读时门控**：读取时同时检查范围级原因与**逐文档可读条件**——对文档所属的每个范围（来源、账号），设该范围最新缺口代次为 g，必须 `verified_epoch[该范围] ≥ g`，否则不可读——**不得以首次抓取、入库、发布时间或 observation\_epoch 替代核验**；推进 `verified_epoch[范围]` 到 g 只有两条路径：(a) **任何带新鲜性下界的存在观测**（首次获取或回访均可）——下界 ≥ `verification_cut_at(g)` 且依据检查通过；无法确定下界的首次获取（缓存或历史内容）不推进；(b) **可靠增量路径每送达一个对象或修订即自动记录**——对其所属每个范围，`verified_epoch[范围] := max(·, 该范围中排序域相同且 cut_position < 送达位点的最新代次)`（相等不构成证明，可另走路径 (a)），并保存送达位点作为 `new_after_cut`** 证明**（绑定范围、代次、位点；只在同一排序域比较，不把 seq 与时间直接比较），无需恢复流程另行发起——否则缺口闭合后经流送达的所有新帖都会永久不可读；两条路径只推进逐文档核验，**不自动清除 account\_inactive、范围级清扫原因或永久墓碑**；cut 尚未确立之前，缺口开始后经任何路径首次观察到的文档一律按未核验处理；**该条件持续生效，不随范围级原因的清除而失效**——范围级原因（`source_gap`、`sync_unverified`）只表示"清扫进行中、整个范围禁读"，清除它不放行任何未核验文档；写入不因来源范围状态被拒，来源控制行不入锁序，resync 期间写入照常进行；逐文档核验记录建索引。**门控覆盖派生对象**：派生对象（Claim、指标结果、话题中心、报告快照）在写入时由血缘计算并携带根来源范围集合；读取时若任一根来源处于门控，结论与指标标"来源核验中"且不进入新报告快照的"完整"级，就绪判定把该来源视为未闭合缺口，向量与全文检索结果对门控来源的文档逐条按核验记录过滤。**独立删除事务**先对控制对象行取 `FOR UPDATE`，再取撤回日志计数行分配序号，更新 availability、撤回代次与扇出责任。CI：删除事务回滚后前沿不停滞；两个撤回事务并发提交，号码与可见顺序一致。所有读取经当前可用性检查。

**删除扇出登记表**：每个保存内容派生数据的存储登记删除处理器；**导出登记表**：报告下载、标注批次、切片清单登记并纳入扇出，**区分受控副本（平台可撤回：系统内标注、受控切片）与非受控副本（用户下载到本地），并记录撤回能力**；平台清理完成只覆盖平台及可验证的受控副本；对非受控副本分别记录"已通知 / 已确认 / 不可验证"，不合并为平台删除成功；**必须强撤回的来源不开放非受控明文导出**；标注优先在系统内完成。

## 6. 并发、可靠性与调度

### 6.1 顺序的建立

入口每分区串行物化后才可领取；分区所有权代次；位点同事务；生产者以 `partition_key` 为消息键；物化时查归档标记。四种序（输入 / `enqueue_seq` / 状态版本 / 输出序号）。生产者流序（`emits[].ordering`）与消费者队列序分开；注册中心检查 causal 类型单一活跃生产者血统并核对 `requires_order`（`causal` 订阅只能指向 `ordering=causal` 的类型，`none | arrival | causal` 枚举见 4.4）。**causal 缺口**：序列域前沿在订阅过滤之前维护并落 PG；序号小于已应用值且身份一致按重复丢弃，**身份不一致报冲突**；大于期望下一号时**直接从 PG 事件表按序号补齐后继续**；补不到即协议违规——暂停该键告警，已收后续事件持久化到暂存表，正常推进位点。计数器键含命名空间。有序域四阶段 + 采集阶段。**键占用表**：有序消费者只领该键最小 `enqueue_seq` 且无在途；重试中的最小任务即使未到 retry\_at 也阻塞同键后项；暂停范围限定失败有序域及必要依赖；同键批量按成功前缀（Demo `max_batch=1`）。富化 join 原语。

### 6.2 三种身份

事件（source + id）/ 任务（租户、命名空间、步骤、输入身份带角色、配置锁）= 消费端去重 / 内容缓存。保留期：回执 ≥ 最长租约 + SDK 重试窗口；任务身份 ≥ Kafka 保留期 + 重投窗口。

### 6.3 失败、重试、背压

重试分层共用预算，尝试预算平台持久化；耗尽先延后；TTL 不作用于状态变更输入；`shed_policy` 默认 never；阀门在采集入口；优先级沿链上传；按资源分别处理；**PG 准入**：提交并发与待提交队列受限，满时 lease/complete 返回 `retry_after`；控制路径预留连接；丢弃留痕；外发箱分区与保留。

### 6.4 合并触发与话题合并

每键一在途 + 刷新标记；结果绑定输入快照；`max_staleness`；合并带 epoch，Demo 短暂排空后合并。

### 6.5 回放隔离

复现 / 重算 / 审计展示；独立命名空间、初始快照、allowlist、预算、虚拟时钟；按 4.6 模式权限表；不恢复已删内容；采集任务不参与回放。

### 6.6 有状态切换

① 停派发记边界 → ② 排空（超时终止者退回待领保留位次）→ ③ 封旧代次（**先登记同时拦截领取与新建的栅栏及默认终结目标（新建任务的事务在作业行锁内复核栅栏并持锁至提交），再按 task\_id 升序锁定全部非终态旧代次任务行并绑定终结目标，然后更新作业 / 代次行（旧代次心跳不再续租），最后扫尾终结未领取或租约失效的旧代次任务**，4.11）→ ④ 迁移并按 `state_compare` 核对 → ⑤ 原子切换 → ⑥ 积压按新版本派发；旧 Manifest 未开始任务形成可审计新身份继承 `enqueue_seq`；Demo 只允许第 ⑤ 步前回退，之后前滚；连接器升级同协议加检查点兼容性。

### 6.7 编排器内核边界

内核只含通用原语；新原语走评审制；复杂分流写路由 Agent；CI 扫描内核业务词。

## 7. 知识层与本体层

**四类知识**：规范型（法规与沿革）、经验型（案例）、**事实型 = 观测记录（文档、传播边、观测账号、互动序列）+ 指标**（按身份查找、图遍历）、主数据型（实体与别名实例、辖区树、事权对照、账号标注、平台渠道目录、采集查询具体内容）；发布期声明归领域包（标签体系、谓词、词库、实体与关系类型定义、指标定义、规则、提示词、模板、法规清单、采集查询模板结构）。观测账号表与传播边表归事实层。  
**本体层**：类型层索引，引用实体类型定义与谓词注册表；关系类型名与边表一致；动作类型引用命令或 WorkflowSpec；溯源基于观察关系，可多跳图查询，不依赖推理证明因果。  
**指标目录与数值治理**：参数化 `metric_id`、不可变 `metric_result_id`、版本化只读视图、槽位引用结果身份、校验作用域含表格图表、兜底扫描、活锁降级、统计数字同时展示底层标签质量记录、案例内数字只作案例内容。  
**去重与口径**：保留原始记录建重复组；四种口径；观测量 / 概率估计 / 接口截断区分。  
**法规引用**：召回混合，引用硬约束，条文框架渲染；精确引文 extraction，适用依据 inference/suggest；拒绝同句认定词。  
**领域包**：`pack.yaml` + `pack.lock`；受限声明式逻辑；golden set 不在包内；升级三类；pack lint；**M0 完成三类内容的 schema 定义，M1 完成加载、锁定、注入**（与第 13 章一致）；M2 夹具第二包。  
**评测体系**：数据四分；逐条、应报事件清单（召回与时延）、端到端、注入样本必做；聚类集合级与排行序关系评测为调节阀；采集覆盖率只做计数；评测语料来自中文源；**聚类缩窗在聚类覆盖中披露**。  
**准确度杠杆**：0 golden set + 漏报 → 1 实体归一化 → 2 指标目录 → 3 近重复建组 → 4 证据绑定前移 → 5 schema → 6 动态少样本 → 7 法条 → 8 片段定位 → 9 交叉校验 + 复核闭环 → 10 来源可信度 → 11 案例检索 → 12 图谱。

### 8.4 调度
