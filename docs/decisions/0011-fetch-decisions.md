# ADR 0011：版本化采集判定与完整组合证明

- 日期：2026-11-04；状态：工程采用，未模拟组织签字。
- 依据：大纲 §4.11、分册一 §1 / §3、总册 §8.3 / §8.4。
- 级别：总册 §11.1 三级影响，新增采集计算入口 / 锁模型和正式规则；没有旧业务消费者、迁移或 A/B/C 裁剪。

## 问题与决定

M0-04 的材料 helper 只有 V1 / V19 一致性检查，旧矩阵只测规模。真实运行时必须先独立判定完整页面，再决定检查点、作业和后继任务意图。M0-05 按功能 PR 推进，本轮 A 完成判定器，后续补载荷 / 配置锁、真实存储适配器和文件集成。

18 行动作和 19 条违规成为两个版本化 YAML 文件，正式枚举域也随表登记。采用 [YAML 1.2.2 的 JSON 兼容语法](https://yaml.org/spec/1.2.2/)，项目仅支持 JSON 流式语法及顶部注释，复用严格 JSON / Pydantic，不增加依赖，也不引入新表达式引擎。条件限封闭字段的 in / not-in，编译为不可变集合；未使用 eval。已实现 CEL 子集用于领域规则，不给这张有限调度表增加进程 / 预算依赖。

所有违规按编号收集，之后才匹配动作；valid 恰好一行。未知页枚举不丢独立合法控制。版本和文件字节摘要共同进入 DecisionPolicyLock，调用方须从平台配置解析，不能只比较 Worker 自报版本。新采集材料入口完整重算 PageResult 后才复用签名材料绑定；原基础 helper 仍保留兼容，不作采集完整校验器。

## 证明与边界

正式矩阵使用生产同一 matcher，独立 oracle 直接逐条翻译 HLD，不读取 YAML。拆分查询下语义不同的 present / failed，轮廓变为 3,686,400，唯一不可达排除 921,600，实际判定 2,764,800；所有行 / 条目都有命中。每个违规组合的全部代码流式 gzip 保存，CI 每 PR 全量并上传 14 天 artifact。

CI 新增 [actions/upload-artifact@v4](https://github.com/actions/upload-artifact/tree/v4) 保存这些证据。v4 默认忽略隐藏目录，因此只对专用 `.cache/fetch-decisions/` 开启 include-hidden-files，目录由脚本写合成数据；缺失附件判错。没有扩大到整个缓存目录或增加应用依赖。

输出是提交意图：行 11 / 12 还需持久恢复预算判断，后继身份 / CAS / I9 / I21、违规受限事务和完整 M0 H11 的服务接线随后完成。有限等价类证明不推导成无限载荷 / 真实来源 / 全部业务正确性证明。

## 兼容、验证和回退

新增两份独立 Schema，不改第一批 / 第二批快照、JCS、HMAC 格式或依赖。详见 [消费规范](../contracts/fetch-decisions-v1.md)、[规则映射](../rule-map/m0-fetch-decisions.md) 和 [dev_memory](../../dev_memory/2026-11-04-m0-05a-fetch-decisions.md)。回退只撤本轮新规则 / 入口 / 快照与 CI 门禁；没有业务数据变化。接入真实配置与消费者后，解释器语义、表内容、版本或锁变化必须显式升级和重新全量验证。
