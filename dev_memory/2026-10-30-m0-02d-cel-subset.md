## 2. 候选调查、失败与最终选择

先核对官方 CEL 语言定义、HLD 推荐的 cloud-custodian/cel-python 和 PyPI。隔离 uv 安装并检查 `cel-python 0.5.0`，随后在初版真实入口测试中发现 `facts.flag + 1 > 0` 没有按预期失败。

进一步独立探针证明其 BoolType 继承 Python int：

| 表达式 | cel-python 0.5.0 | 选定 Rust 绑定 0.10.0 |
| --- | --- | --- |
| true + 1 == 2 | true | TypeError |
| true == 1 | true | false |
| [true] == [1] | true | false |
| 1.0 + 1 > 0 | true | TypeError |
| int64 最大值 + 1 | 溢出错误 | OverflowError |

这些反例影响定级规则语义，不能通过改测试预期掩盖。未给旧库添加自制运算符修补；移除初版 AST / Lark 守卫，改为使用 `common-expression-language 0.10.0` 的同一编译结果做静态引用检查与求值。最终版本不是两个引擎混用，也没有源码正则白名单。旧库探针 `has(1)` 也返回 true，最终引擎会在编译时拒绝。

最终依赖 `common-expression-language>=0.10.0,<0.11`，uv.lock 锁定 0.10.0。它是 Rust CEL 绑定、Apache-2.0；macOS ARM64 / Python 3.12.12 使用预编译 wheel。净新增 common-expression-language、prompt-toolkit 3.0.53、shellingham 1.5.4、typer 0.27.3、wcwidth 0.9.4；Rich / Pygments 原已存在。没有使用随库 CLI、可选 stdlib 扩展或用户回调。

cel-python、RE2、Lark、Pendulum、jmespath 等候选依赖均从应用锁文件移除。曾隔离检查官方 C++ Python 绑定的接口，没有加入本项目依赖。替换推荐候选 / 引入组件按总册 §11.1 二级实现变更信息记录在 ADR 0005 / PR：动机、比较、影响、测试与回退均明确。保持 CEL，不改 HLD 原件与冻结语义，无 A/B/C 裁剪，不虚构其他人工角色会签。

## 3. 实现结构和输入协议

新增两个 runtime 内部模块，无 SDK / contracts 导出或业务调用方：

- `runtime/core/cel_rules.py`：公开原型 `evaluate_rule(expression, facts, *, timeout_seconds=2.0) -> bool`、固定错误类型 RuleError、准入编码 `_encode_request` 和进程生命周期 `_run_worker`。
- `runtime/core/cel_worker.py`：独立 CLI 入口；重复输入验证、编译、函数引用白名单、执行、精确 bool 验证，stdout 只输出 `{"result": true|false}` 或 `{"error": 固定码}`。

输入只允许原生 JSON 类型，键必须原生 str。CEL int 范围为 `[-2**63, 2**63-1]`，不同于 JCS 的 Python 安全整数范围；json.dumps / json.loads 保留整数，不先经过 float。double 必须有限。tuple、set、bytes、callable、模型或自定义类型不转换；字符串与键必须可编码为 UTF-8。

准入常量：表达式 4096 UTF-8 字节；请求 65536 字节；每个输入 dict / list 至多 128 项；总输入节点含键 1024；嵌套深度 16；每个字符串 / 键 4096 UTF-8 字节。先检查容器 len 再扫描键，先检查字符串字符数再做 UTF-8 编码，避免对已知超限对象先做大规模复制。循环输入按深度 / 节点上限拒绝。

错误码：invalid_input、input_limit、syntax、unsupported、evaluation、non_boolean、timeout、worker_failure。错误不是 false；合法 false 单独正常返回。协议精确检查键和 bool 类型，额外字段、未知错误码、非 JSON、过长响应或非零退出统一 worker_failure。

## 4. 函数封闭与时间预算

只提供全局 JSON `facts`。CEL 核心表达式、字面量、比较、算术、逻辑、索引、条件、集合宏可以使用；宏局部变量由引擎管理，可嵌套。最终只允许 bool。全局未绑定变量不会获得宿主对象，实际读到时由 CEL 求值报错；未绑定引用处于可短路分支时按 CEL 本身语义处理。

编译后调用 `Program.functions()`，要求所有引用属于代码内 ALLOWED_FUNCTIONS：核心运算符（含 @in / @not_strictly_false 宏展开运算）以及 size / contains / startsWith / endsWith。用户不能传入函数实现、Context、运行器或白名单。has / all / exists / exists_one / map / filter 由引擎展开，引用检查针对实际展开后的完整编译对象。

now、random、custom、timestamp / duration、matches、类型转换和 type 均不在白名单；即便位于 true || custom(...) 的死分支也拒绝。字符串 / 注释里的同名字面文本不误报。没有 Python eval、额外规则脚本或可选 stdlib 注册。

每次启动 `[sys.executable, '-m', 'runtime.core.cel_worker']`，固定 repo 根目录为 cwd，输入仅放 stdin，stderr=DEVNULL。communicate 缺省截止时间 2 秒、调用范围 `(0,5]`，覆盖 worker 导入、编译、检查和执行；父进程准入与 OS 创建本身不声称受该计时器覆盖。超时 / 调用中断时 kill + communicate 收尾，并退出 Popen 上下文回收；不使用仅超时等待的线程池。

worker 禁用 Python 库日志，父端不返回 stderr，不向异常消息拼入表达式或 facts。Rust 原生异常 / 崩溃按非零退出处理，父端不会把裸输出作为成功。没有日志 / span 内容采集。

## 5. 测试与实际结果

新增 `tests/unit/test_cel_rules.py` 111 项测试，均使用实际固定 worker（损坏协议测试只在测试中替换为真实 Python 子进程）：

- 规则 true / false、三元、数值、字符串、集合索引 / membership、全部核心宏、嵌套、null / missing、int64 两端与 2**53+1 保真、CEL 负数整除 / 取余。
- 候选失败的类型语义回归：true 与 1、列表元素 bool / int、混合算术、溢出；不允许非布尔结果被 truthiness 转换。
- 白名单包含死分支、任意扩展 / 时间 / 正则 / 转换拒绝，注释和字符串反例。
- 输入类型与所有规模上限、循环、UTF-8 字节、空表达式、预算非法值、边界 128 项 / 4096 字符通过。
- 真实 1 ms 启动超时；128 元素五层 all（128**5 潜在组合）在 0.3 秒预算下超时；检查实际子进程 returncode 和 os.kill(pid,0) 证明已不存在，再运行正常 false 成功。
- 真实 CLI stdout / stderr 无合成来源标识；损坏协议、额外键、非 bool、未知错误码、过长响应、异常退出以及 worker 自身输入边界。

实际执行结果：

- `make test-cel`：111 passed，最终本地约 8 秒。
- `make check`：288 passed、29 个集成用例按 marker 排除；总收集 317 项。8 条 import-linter 契约、连接器导入检查、迁移链 1 revision 与锁文件检查通过。
- 新增 3 个 Python 文件的 AI header / 日期格式、函数 docstring 和 AST 语法检查、`git diff --check` 通过。

初次测试的类型失败推动替换库；换库后一个宏错误分类预期由 syntax 调整为 unsupported，因为错误 arity 没有展开、保留为不在白名单的函数 all，仍明确拒绝。没有修改正确类型语义来迁就候选缺陷。

远端 CI 必须继续执行完整 PG / Kafka / observability 门禁；本轮未重复扰动本地容器和故障拓扑。交付 [PR #5](https://github.com/kai2dot0/april_public_sentiment_multi_agent/pull/5)，实现提交 `3897e35`；最终提交的 CI、merge SHA 和合并状态以该 PR 记录为准，全部检查通过后才合并，不把未执行项记作通过。

## 7. 接手、边界与回退

先读本 memory / ADR，随后读父入口、worker、111 项测试和规则映射。下一项是 M0-02E：Pydantic/schema/digest 元数据、未知枚举、Worker 传输形态与穷举规模验证。语义包投影 / 签名仍按 M0-04，未纳入本轮。

本模块没有精确 fuel / 操作计数、AST 成本证明、单独的中间派生集合上限或硬内存限制。嵌套宏可产生乘法工作量，由超时终止；不保证截止时间前的内存峰值。没有 cgroup、进程组后代清理、网络隔离、凭据剥离或只读文件系统，不能把独立进程等同完整沙箱。后续 M0-02F / M0-06 补 OS 约束、并发准入和监督器；当前没有表达式宿主 I/O 函数，但不替代 OS 执法。

M1 接领域包 / risk-grader 时，须将规则和引擎版本、预算、输入 schema 锁进执行配置；结合 YAML 决策表全组合穷举、Rule Evidence、decision Claim、异常策略和回放评测。不能因为正常谓词返回 bool 就宣称规则定级业务已实现。当前不做缓存或持久编译对象，每次单独进程有启动开销，未做容量压测；后续复用进程前要保留可强制终止和无状态污染约束。

无数据库迁移 / 持久数据或身份变化。当前撤销依赖 / 模块 / 测试即可回退，不自动降级到 cel-python 或 Python eval；后续有审计与回放结果时，引擎升级需保留版本并做语义及业务规则评测，不能静默替换。
